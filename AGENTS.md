# AGENTS.md

Personal portfolio of Mario Vizcaino. Astro 7 static site, bilingual (EN default at `/`, ES at `/es/`), deployed to GitHub Pages by `.github/workflows/deploy.yml` on push to `master`.

**Status:** live at https://mariovzc.github.io since 2026-10-12. Work happens directly on `master` — every push deploys in ~2 minutes, so run `make check && make test` before pushing. Future work is tracked in [`docs/BACKLOG.md`](docs/BACKLOG.md).

## Hard rules

- **Never run `node`, `npm` or `npx` on the host.** Everything runs in Docker via `make`:
  `make install | dev | stop | build | preview | check | test | test-unit | test-e2e | build-soon | preview-soon | lighthouse | og | favicons | add pkg="x" | add-dev pkg="x" | format | clean`.
- Never commit `resume2026.pdf` or any root `*.pdf` (personal data).
- Zod comes from `astro/zod`, not `astro:content`.
- Astro 7 uses a Rust compiler: close every non-void tag; no block elements inside `<p>`.
- Internal links always end with `/` (`trailingSlash: 'always'`). Build them with `localizePath()`.
- Keep logic in pure functions under `src/lib/` or `src/i18n/` with Vitest tests; `.astro` files only render.
- `astro.config.mjs` sets `image: { dangerouslyProcessSVG: true }` because the fixture project covers are SVG: sharp rasterizes them to WebP/PNG (covers use `format="webp"`), which requires the flag. Do not remove it until every project image is raster (PNG/JPG/WebP).
- Playwright (`playwright.config.ts`) and `scripts/lighthouse.mjs` run `astro preview --ignore-lock` because a stale preview lock can persist in the shared Docker node_modules volume. Keep the flag.
- `npm run dev` (`make dev`) also uses `--ignore-lock`: inside Docker every new container reuses low PIDs, so a stale `.astro/dev.json` from a dead container looks alive and blocks startup. If dev serves stale content after a schema change (e.g. "x is not iterable" for a new defaulted field), rebuild the content cache once: `docker compose run --rm --service-ports app npx astro dev --host 0.0.0.0 --force`.

## Layout

- `src/content/projects/{en,es}/<slug>.mdx` — one file per project per language; same slug links translations. Schema in `src/content.config.ts`.
- `src/content/profile/{en,es}.yaml` — fullName (optional legal name: footer + JSON-LD `alternateName`; also written in the bio so it is visible text), alternateNames (other search combinations, JSON-LD only), bio, services, experience, education, certifications (both optional, default `[]`; the Education section hides when both are empty), heroFacts (optional, max 2 `{value, label}` proof points under the home hero, between the computed years and the location), services (each may set optional `tools` and `project` — the slug of the project that proves it; they feed the home "What do you need built?" picker in `Services.astro`: radios + `:has()`, no JavaScript), stack (frontend, backend, tools and `practices` — security & quality standards shown as skills in About, not as a service), contact. There is deliberately no CV download (visitors must contact first); do not add a `cv` field or public PDF.
- `src/i18n/{en,es}.json` — UI strings; keys must match in both files (unit test enforces it).
- `src/lib/` — `projects.ts` (localization/fallback), `sitemap.ts` (fallback-page sitemap exclusion), `seo.ts`, `llms.ts`, `robots.ts`, `theme.ts`, `webmcp-tools.ts`, `site-data.ts` (only file that reads collections).
- `src/views/` — page bodies shared by EN/ES routes in `src/pages/`.
- Design tokens in `src/styles/global.css` ("Lime on ink": dark by default (`resolveTheme()` + inline script in `BaseLayout.astro`; light only when the visitor picks it), near-black canvas with a green tint, lime `#b8f24a` as the one accent, flat lime field for `.hero-surface`, Plus Jakarta Sans 800 headings). Shared component classes there: `.tile`, `.tile-hover`, `.pill*`, `.chip`, `.eyebrow` (small muted data label, sentence case — no uppercase labels above section titles), `.hero-surface` (lime field: home contact and the end-of-project "Have a similar problem?" CTA), `heavy` utility.
- Favicons (`public/favicon-{32,48}.png`, `apple-touch-icon.png`, `icon-{192,512}.png`) are generated from the monogram `src/assets/brand/avatar.png` (512×512, rendered with Playwright) by `scripts/favicons.mjs` (`make favicons`; small sizes get a circle mask); `public/site.webmanifest` references the 192/512 icons. Regenerate after changing the avatar.
- `src/lib/profile.ts` — `yearsOfExperience()` and `splitHeadline()` for the home hero (`src/components/astro/HomeHero.astro`: headline split at " — " into h1 + lead, CTA mailto with subject, AI pipeline panel linking to the featured project, facts row).
- Social preview images: `src/assets/brand/og-{en,es}.png`, generated by `scripts/og-image.mjs` (`make og`) from the profile YAMLs. They live in `src/assets` (not `public/`) so Astro emits them with a content hash — a new URL on every change forces WhatsApp/LinkedIn/X to refresh cached previews. Run `make og` after changing name, role or headline.

## Production mode

- `.github/workflows/deploy.yml` builds with `PUBLIC_COMING_SOON: 'false'` (full site). Setting it to `'true'` publishes only a noindex "coming soon" page (no project pages, minimal `llms.txt`, sitemap with the two home pages). `make build-soon` / `make preview-soon` show that mode locally.

## E2E fixtures

- The real site only ever contains the projects in `src/content/` (`make dev`, `make build`, deploy, `make lighthouse`). Sample projects do not belong there.
- `make test-e2e` builds with `CONTENT_ROOT=tests/fixtures/content` (resolved by `src/lib/content-root.ts`, used by `src/content.config.ts` and the sitemap scan in `astro.config.mjs`) and runs Playwright against that build. Fixtures: `tests/fixtures/content/{projects,profile}` (full, EN-only and confidential projects; fixture profile "Sample Person") and `tests/fixtures/assets/projects/sample/`. Fixture mdx image paths are relative (`../../../assets/...`).
- E2E specs assert on fixture content, never on real content. Add new e2e scenarios as fixtures, not as real projects.
- The fixture build rewrites the shared `.astro/` (content assets, data store) that a running `make dev` also reads; `make test-e2e` therefore ends with `astro sync` for the real content (even when tests fail). If dev ever shows `LocalImageUsedWrongly` for a real cover, run `make stop && make dev`.

## Common tasks

- **Add a project:** create `src/content/projects/en/<slug>.mdx` (and optionally `es/<slug>.mdx`), put images in `src/assets/projects/<slug>/`, set `featured: true` to list it on the home page and an `order` after 0, run `make check && make test`. A missing ES file falls back to EN automatically. Covers are 1600×1000; App Store screenshots can be pulled from the iTunes lookup API and composed on the green gradient; architecture diagrams are rendered to PNG with Playwright (never SVG `<text>`, which sharp can't rasterize without fonts).
- **File names:** project files must be lowercase kebab-case (`my-app.mdx`); a unit test enforces it because `astro.config.mjs` derives slugs from file names for the sitemap.
- **Hide a project:** `draft: true`. Drafts are still visible in the public GitHub repo.
- **Add a UI string:** add the key to both `en.json` and `es.json`.
- **Change domain:** update `SITE` in `astro.config.mjs` and the `SITE` constant in `tests/e2e/site.spec.ts`, add `public/CNAME`, configure DNS (see README), then regenerate the OG images with `make og` (it reads the domain from `astro.config.mjs` and name/role/headline from `src/content/profile/{en,es}.yaml`).
